# Product Requirements Document (PRD)

## Project Name

GhostIntel

## Project Type

Autonomous Company Intelligence and Knowledge Graph System with Deterministic Offline Reasoning

---

## 1. Overview

GhostIntel is an autonomous company intelligence system that converts a company domain into structured, explainable, and graph-based business intelligence. The system uses an online crawling layer powered by Crawl4AI to collect all publicly accessible pages of a given domain, freezes the content locally, and then performs all extraction, validation, classification, and reasoning fully offline using deterministic rules, heuristics, and graph-based logic.

GhostIntel produces confidence-weighted company profiles, detects contradictions, infers hidden business and engineering signals, and represents all knowledge in both tabular and graph-based forms. Industry classification is performed using a standardized SIC taxonomy to ensure consistency, auditability, and zero hallucination.

The core philosophy of GhostIntel is strict separation between data acquisition and intelligence, and strict separation between extracted facts and classification ontologies.

---

## 2. Problem Statement

Most company intelligence platforms rely on cloud-based AI models and opaque classification logic. They often mix extracted facts with inferred labels, leading to inconsistent industry tagging, poor explainability, and non-reproducible outputs.

Additionally, many tools treat industry classification as an LLM-driven task, making it impossible to audit or standardize at scale.

GhostIntel addresses this gap by producing deterministic company intelligence outputs and linking them to a fixed, versioned industry taxonomy using SIC codes.

---

## 3. Objectives

* Crawl and collect all relevant pages of a company domain automatically
* Freeze website content locally for deterministic analysis
* Extract structured company intelligence using rule-based methods
* Assign confidence scores and evidence to extracted fields
* Classify companies using standardized SIC codes
* Detect contradictions and ambiguous signals across pages
* Build a reasoning-ready knowledge graph
* Support batch processing of 100 to 150 companies
* Provide a clean React-based UI for exploration
* Ensure deterministic, auditable outputs with no mandatory LLM dependency

---

## 4. Input and Output

### Input

* Company domain name. Example: infynd.com

---

### Intermediate Artifacts

* Locally stored website snapshot collected via Crawl4AI
* Normalized text and metadata corpus
* Extracted entity candidates with evidence

---

### Output Overview

GhostIntel produces **two primary outputs**:

1. **Company Intelligence Output**. Dynamic, per-domain
2. **Industry Taxonomy Reference**. Static, versioned

These outputs are designed to work together through deterministic joins.

---

### 4.1 Output A. Company Intelligence Output

This output represents the final analyzed intelligence for each company.
Each row corresponds to exactly one company domain.

#### Output Format. Tabular or JSON

**Core Fields**

* `domain`
  Unique identifier for the company. Primary key.

* `long_description`
  Detailed company description extracted from authoritative pages.

* `short_description`
  Concise summary derived from hero sections, meta descriptions, or taglines.

* `sic_code`
  Numeric Standard Industrial Classification code.
  Nullable if classification confidence is insufficient.

* `sic_text`
  Human-readable description of the SIC code.
  Derived strictly from the taxonomy reference.

* `sub_industry`
  Normalized sub-industry label derived via SIC lookup.

* `industry`
  Mid-level industry grouping derived via SIC lookup.

* `sector`
  Top-level sector grouping derived via SIC lookup.

* `tags`
  Optional keyword-based enrichment signals.

#### Properties

* All non-derived fields include confidence scores and evidence references internally
* Missing values are allowed and explicitly represented
* No industry or sector labels are inferred without a valid SIC mapping

This output represents the **authoritative company intelligence layer**.

---

### 4.2 Output B. Industry Taxonomy Reference

This is a static, versioned reference dataset used for classification.

#### Output Format. Tabular or JSON

**Fields**

* `sic_code`
  Primary key.

* `sic_description`
  Official SIC activity description.

* `sub_industry`
  Normalized sub-industry grouping.

* `industry`
  Normalized industry grouping.

* `sector`
  Top-level sector grouping.

#### Properties

* This dataset is not generated by GhostIntel
* It is maintained, versioned, and audited separately
* Changes to this file affect classification deterministically

This output represents the **classification ontology layer**.

---

### 4.3 Relationship Between Outputs

Company classification is performed by joining the two outputs on `sic_code`.

```
Company Intelligence Output.sic_code
              ↓
Industry Taxonomy Reference.sic_code
```

All industry, sub-industry, and sector fields in Output A are derived exclusively through this join.

## 5. System Scope

### Allowed Online Operations

* Website crawling and page discovery using Crawl4AI
* HTML, metadata, and structured data collection

### Strictly Offline Operations

* Text parsing and normalization
* Rule-based entity extraction
* SIC classification using keyword and rule matching
* Confidence scoring and validation
* Knowledge graph construction
* Heuristic-based inference

---

## 6. Core Features

### 6.1 Domain Crawling and Snapshot Freezing

GhostIntel crawls all reachable internal pages of a domain using Crawl4AI and stores a normalized local snapshot. All downstream processing operates only on this snapshot.

---

### 6.2 Deterministic Information Extraction

Structured data is extracted using:

* DOM analysis
* Regex patterns
* Schema.org parsing
* Footer and legal text inspection
* Careers and hiring signal analysis

---

### 6.3 SIC-Based Industry Classification

Industry classification is performed by:

* Matching extracted descriptions against SIC keyword maps
* Assigning a single SIC code or leaving it null
* Deriving all higher-level labels via taxonomy lookup

No free-text industry inference is permitted.

---

### 6.4 Confidence and Evidence Attribution

Each extracted and classified field is supported by:

* Confidence scores
* Source page references
* Textual evidence snippets

---

### 6.5 Contradiction Detection

The system detects inconsistencies such as:

* Multiple SIC candidates with similar confidence
* Conflicting descriptions across pages
* Inconsistent branding or naming

All contradictions are explicitly reported.

---

### 6.6 Knowledge Graph Construction

Entities and relationships are modeled as a graph:

* Company → Industry → Sector
* Company → Products
* Company → Locations
* Company → Technologies

The graph is derived directly from Output A and Output B.

---

### 6.7 Batch Intelligence Mode

Batch processing supports:

* Cross-company sector clustering
* Industry distribution analysis
* Outlier detection
* Comparative maturity scoring

---

## 7. System Architecture

### Backend

* Language. Python
* Framework. FastAPI
* Crawling. Crawl4AI
* Parsing. BeautifulSoup
* Classification. Rule engine + SIC taxonomy
* Knowledge Graph. NetworkX
* Validation. Pydantic

---

### Frontend

* Framework. React jsx
* Styling. Tailwind CSS
* Visualization. Graph visualization libraries

UI supports inspection of company profiles, industry classification, evidence, and graph relationships.

* No mandatory LLM dependency
* Fully auditable classification logic
* Reproducible batch runs
* Minimal infrastructure footprint
